# Подготовка исходников к GitHub

Экспорт содержит студию: server, studio, runtime, library, templates, tools и install. Дополнительно разрешены файлы сборки, package.json и lock-файл, README, существующие NOTICE/LICENSE, .gitignore/.gitattributes, два workflow GitHub, rules/astra-method-13.md и только два документа: docs/astra-method-13.md и этот файл. Остальные docs и rules не экспортируются.

Не включаются пользовательские projects, temp, trash, рендеры, node_modules, настройки и переписка .moootion, внутренние документы и любая Git-история. Демо в templates и материалы library — поставляемые материалы студии; перед публичной загрузкой их происхождение и права проверяются по NOTICE и метаданным. Экспортёр не добавляет лицензию и не переписывает авторство README/NOTICE.

## Два независимых Git-хранилища

Git исходников предназначен для кода студии. В новых установках история пользовательских проектов находится в приватном bare-хранилище `.moootion/history.git` с рабочим деревом `projects/`; оно не экспортируется и не должно получать публичный remote.

Если в прежнем корневом Git уже есть история проектов, студия сохраняет её в прежнем режиме, без переноса и переписывания коммитов. Поэтому рабочий `.gitignore` старой установки намеренно не игнорирует `projects/`. Экспортёр генерирует отдельный `.gitignore` только в копии, с исключением `projects/` и других приватных данных. Свежий исходный репозиторий не содержит старой истории и использует отдельное приватное хранилище. Преобразование явно записано в inventory, включая SHA256 исходного и экспортированного файла. Нельзя выполнять `git add -f projects` в репозитории исходников или добавлять публичный remote к приватной истории.

## Безопасный экспорт

Из корня рабочей студии сначала выполните только аудит, затем экспорт в отсутствующий каталог вне рабочего дерева:

```sh
node tools/publish.mjs --audit ../moootion-source
node tools/publish.mjs ../moootion-source
```

Аудит ничего не записывает. Экспорт не вызывает Git, сеть, агентов или платные сервисы. Он создаёт рядом четыре объекта:

- новый каталог исходников;
- `moootion-source.zip` с теми же байтами файлов;
- `moootion-source.inventory.json`: полный перечень, размеры, SHA256, исключения и замечания аудита;
- `moootion-source.sha256`: хеши ZIP, inventory и всех файлов.

Inventory и SHA256 остаются рядом с каталогом, не внутри репозитория. ZIP не содержит `.git` или служебную историю. ZIP хранится без сжатия, чтобы не требовать внешних архиваторов. Метод 13 копируется побайтово; `.gitattributes` задаёт для него `-text`, сохраняя исходные CRLF и проверяемый SHA256.

Экспортёр отказывает даже для существующего пустого назначения, для существующего ZIP/sidecar, для совпадения с исходником, его предка или потомка. Удаления и зеркалирования нет. Проверяются все существующие компоненты пути; символические ссылки и Windows junction запрещены. Среди выбранных исходников также запрещены ссылки, hardlink, специальные файлы, неожиданные форматы, файлы ключей/учётных данных, распознаваемые секреты и персональные домашние пути. Пределы: 10 MiB на файл, 128 MiB суммарно. Диагностика секрета содержит путь, номер строки и категорию, без содержимого строки.

Известные приватные каталоги исключаются по имени; неожиданный файл учётных данных внутри разрешённого дерева блокирует экспорт. Имена клиентов в тестовых фикстурах сами по себе не считаются секретом; токены и персональные пути проверяются в тестах наравне с остальным кодом. Замечания о брендах и бинарных материалах требуют просмотра inventory: эвристический сканер не доказывает отсутствие всех возможных секретов или наличие прав на ассеты.

При ошибке записи могут остаться только вновь созданные неполные выходные файлы. Экспортёр не удаляет их автоматически и не продолжает поверх них. Осмотрите результат и выберите новое назначение. Не изменяйте исходники и пути назначения во время экспорта: проверки ссылок не являются защитой от злоумышленника, одновременно меняющего файловую систему.

## Проверка пакета

Проводите установку зависимостей и тесты в отдельной копии, чтобы доставляемый каталог оставался чистым. Не добавляйте node_modules или ссылку на них внутрь ZIP/публичного пакета.

```sh
npm ci
npm run typecheck
node --test tools/publish.test.mjs
node --import tsx --test server/astra-guidance.test.ts server/project-history-git.test.ts server/codex.test.ts server/codex-choreography.test.ts server/codex-connectors.test.ts server/claude-boundary.test.ts
```

Эти тесты используют локальные фикстуры и подменённые протоколы, не запускают модель и не вызывают платную генерацию. `.github/workflows/check.yml` выполняет тот же набор и аудит экспорта на Node.js 22. Существующий release workflow и его платформы сохранены; установка npm-зависимостей в CI требует сети. Release workflow отличается от проверки исходников: по тегам `v*` он создаёт релизы, поэтому не отправляйте такие теги до отдельного решения о выпуске.

## Ручная загрузка после проверки

Следующие команды — инструкция для владельца, экспортёр их не выполняет. Создайте пустой репозиторий GitHub через интерфейс, затем выполните команды **только внутри нового каталога исходников**, не в рабочей студии и не в `.moootion/history.git`:

```sh
cd ../moootion-source
git init -b main
git add .
git status --short
git diff --cached --stat
# После просмотра состава и отсутствия пользовательских данных:
git commit -m "Import Moootion source with Astra method 13"
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

Замените OWNER/REPOSITORY своим адресом. Не используйте force-push, не добавляйте исходный служебный Git как remote и не включайте sidecar-файлы с результатами локальной проверки в коммит автоматически.
