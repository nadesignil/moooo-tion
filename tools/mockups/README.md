# Мокапы для «Оживления скриншота»

Библиотека: `library/mockups/<id>/{device.png, thumb.png, meta.json}` + `index.json`.
Экран в `device.png` прозрачный; `meta.screen` — прямоугольник экрана (контент кладётся ПОД устройство).

1. `cut_device.py export.png out/` — стандартный мокап из экспорта Figma (узел 201:16, 2×): прозрачный фон и экран.
2. Материалы: Magnific, Nano Banana Pro, image-to-image по референсу «устройство с зелёным экраном» (9:16, 2k),
   промпт — `meta.prompt`; затем `images_remove_background`.
3. `process_material.py cutout.png library/mockups/iphone-17-air out/ [pad]` — без растяжения устройства:
   дыра экрана стандартных пропорций накрывает зелёное, остаток зелёного — чёрная рамка, Dynamic Island стандартный,
   таблетка на рамке закрашивается материалом (`pad` — сколько вокруг неё перекрашивать; 1 — почти не трогать,
   для зеркального хрома, где тёмные блики похожи на таблетку).
4. `review_mockups.py library/mockups review.png [ids]` — лист с UI во весь экран: пропорции, остров, артефакты.
5. Рамки без экрана (дыра уже прозрачная, 2026-10-26: рамки владельца из Magnific, заменили 20 материалов —
   старые в `trash/mockups-old-2026-10-26/`): `import_frames.py frames.json library/mockups` — обрезка, дыра
   заливкой от центра, экран стандартных пропорций поверх дыры (заходит под рамку на 2–9 px), стандартный
   Dynamic Island дорисовывается (`"noIsland": true` в frames.json — не рисовать).
   Орнаментальные рамки (ветки поперёк экрана, шипы внутрь): дыра автоматически не находится — в frames.json задать
   `"screen": {x, y, w, h, r}` по внутреннему краю рельса телефона в обрезанном device.png (так сделаны chrome-tribal,
   chrome-roses); пропорции экрана скрипт всё равно приводит к стандартным.
